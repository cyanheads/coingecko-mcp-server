# 0.1.3 — 2026-09-21

## Changed

- **HTTP now serves stateless by default**: `src/index.ts` declares `createApp({ sessionMode: 'stateless' })` (mcp-ts-core 0.13.1) and `.env.example` sets `MCP_SESSION_MODE=stateless`, matching the Docker image, which already did. Previously, a source or `npx` HTTP run with `MCP_SESSION_MODE` unset resolved `auto` → stateful. An explicit `MCP_SESSION_MODE=stateful` still overrides the new default, and stdio is unaffected. ([#3](https://github.com/cyanheads/coingecko-mcp-server/issues/3))
- **`@cyanheads/mcp-ts-core` ^0.12.3 → ^0.13.6.** Argument rejections now arrive as an `isError` result carrying `structuredContent.error` (code -32602, [mcp-ts-core#377](https://github.com/cyanheads/mcp-ts-core/issues/377)), plus `data.reason: "invalid_arguments"` and a `Recovery:` hint naming the accepted keys, the expected type, or the missing fields ([mcp-ts-core#445](https://github.com/cyanheads/mcp-ts-core/issues/445)). Pre-validation now case-folds an undeclared key to an exact single match (e.g. `vsCurrencies` → `vs_currencies`), repairs one JSON-stringified array after a failed parse, and drops a fixed list of client-added root keys — advertised `inputSchema` is unchanged ([mcp-ts-core#452](https://github.com/cyanheads/mcp-ts-core/issues/452), [#453](https://github.com/cyanheads/mcp-ts-core/issues/453), [#234](https://github.com/cyanheads/mcp-ts-core/issues/234)).
- **Tool error `content[]` text now closes with `(reason <reason>)`**, adding ` · retryable`/` · not retryable` only when the error declares `retryable`; `structuredContent` is unchanged ([mcp-ts-core#458](https://github.com/cyanheads/mcp-ts-core/issues/458)).
- **Upstream HTTP 500 classifies as `ServiceUnavailable` (-32000)** instead of `InternalError` and is retried; a 501 carries `retryable: false` and is not retried ([mcp-ts-core#323](https://github.com/cyanheads/mcp-ts-core/issues/323)).
- **The server card `/.well-known/mcp.json`** publishes the resolved session mode under `_meta["io.github.cyanheads.mcp-ts-core/sessionMode"]` ([mcp-ts-core#387](https://github.com/cyanheads/mcp-ts-core/issues/387)); `SIGTERM`/`SIGINT` now end the process explicitly once shutdown settles ([mcp-ts-core#435](https://github.com/cyanheads/mcp-ts-core/issues/435)).
- **`parseEnvConfig` reads an empty value or an unsubstituted `${…}` placeholder as unset** ([mcp-ts-core#427](https://github.com/cyanheads/mcp-ts-core/issues/427)) — this server's own `emptyAsUndefined` preprocess guard for `COINGECKO_API_KEY` is removed; behavior is unchanged (new tests pin `""`, the placeholder, and a real key).
- **Bun engines floor** `>=1.3.0` → `>=1.4.0`, from the framework's own floor (mcp-ts-core 0.12.9).
- **Development skill tree moved `skills/` → `framework-skills/`** ([mcp-ts-core#428](https://github.com/cyanheads/mcp-ts-core/issues/428)), so a Claude Code or Codex plugin install no longer loads it as plugin skills; devcheck/lint tooling synced to match.
- **Error-contract entries the service layer throws** now carry `thrownBy: 'service'` — lint-only metadata, `tools/list` is byte-identical.
- **Repo hygiene:** README restructured into overview + capability reference; GitHub issue templates gain framework-vs-server routing guidance and auto-assignment; adds the sanctioned `codeql.yml` workflow, `funding` links, and the `audit:fix` script.

## Fixed

- **Plugin manifests no longer overwrite a user's exported `COINGECKO_API_KEY`.** `.claude-plugin/plugin.json` and `.codex-plugin/mcp.json` both set `"COINGECKO_API_KEY": ""`, replacing an exported key. `plugin.json` now declares `userConfig.coingecko_api_key` referenced as `${user_config.coingecko_api_key}`; `mcp.json` forwards the host's `COINGECKO_API_KEY` through `env_vars`.
